# Технические пояснения

## Модель данных и неизменяемость

`dataclass` генерирует конструктор, сравнение и представление объекта.
`__post_init__` проверяет значения после конструктора. `frozen=True`
запрещает обычное изменение полей: ID детали в словаре не разойдётся с
`item.item_id`, а корректная деталь не станет некорректной после добавления.
Для нормализации при создании используется `object.__setattr__`.

Уникальность ID проверяется каталогом, поскольку отдельная сущность
не имеет доступа к идентификаторам остальных элементов коллекции.

## Поиск и оценка сложности

`get` обращается к `_items[item_id]`. Словарь использует хеширование:
получение выполняется за O(1) в среднем, а в худшем случае - за O(n).
Поиск по имени просматривает все детали, преобразуя запрос и имена методом
`casefold`. При ограниченной длине строк его сложность - O(n). В общем
случае дополнительно учитываются длины строк и стоимость поиска подстроки.

Поиск возвращает новый кортеж. Порядок результатов совпадает с порядком
добавления. `tuple` защищает коллекцию результатов, а `frozen=True` - поля
самих деталей.

## Атомарная загрузка

`load_catalog` сначала читает документ и создаёт список проверенных объектов.
`replace_all` создаёт временный `Catalog`; при повторном ID его конструктор
выбрасывает исключение. Присваивание `self._items = replacement._items`
выполняется только после успешного построения временного каталога.
Исходное состояние не меняется до этой строки.

Это атомарность относительно ошибок загрузки в однопоточном приложении.
Многопоточные транзакции и атомарная файловая запись здесь не реализованы.

## Добавление проверяемого поля

Порядок добавления поля `serial_number: str`:

1. Добавить поле в `AviationPart` и его имя в `PART_FIELDS` в `constants.py`.
   `TEXT_FIELDS` строится из этого списка, поэтому непустая строка будет
   проверяться автоматически. Особые условия описать в `__post_init__`.
2. Добавить аргумент CLI и передавать его конструктору.
3. Обновить тестовую фабрику, пример JSON, README и тест round trip.
4. Дополнить тесты: пустое значение, неверный тип и особое ограничение поля.

`asdict` сохранит новое поле автоматически. Существующий загрузчик требует
точный набор полей. Совместимость со старыми файлами
обеспечивается новой версией формата и миграцией. Изменение набора обязательных
полей требует явного изменения контракта формата.

## Проверка частично повреждённого документа

Проверка реализована в `tests/test_storage.py`, тест `test_bad_second_record_is_atomic`:
исходный каталог содержит деталь `old`, документ - корректную `new-1` и
повреждённую `new-2`. Проверяется `CorruptedFileError`, сохранность `old`
и отсутствие `new-1`. Параметризация перебирает поля и неверные типы.

Дополнительный сценарий: год второй записи содержит строку `"2024"`,
первая запись остаётся корректной. После ошибки `list(catalog)` сравнивается
с исходным списком; идентичность старого объекта проверяется оператором `is`.

## Иерархия исключений

Все предметные исключения являются разновидностями `CatalogError`.
Обработчик CLI ловит общий класс и единообразно выводит сообщение.
Для сущности и каталога наследование не требуется: у них разные обязанности,
и отношения «является разновидностью» между ними нет.
